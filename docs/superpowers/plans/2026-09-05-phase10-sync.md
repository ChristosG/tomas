# Dimitris' App — Phase 10 (Sync) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chris and Dimitris' father install the same APK on their own phones as caregivers, add words and voices from home, and watch progress, through a tiny self-hosted sync server on one of their own web servers. No third-party backend.

**Architecture:** A dependency-free Node 22 server (`server/`) storing a row log (JSON lines, last-write-wins per table+id) and media by SHA-256, behind a bearer token and the owners' TLS reverse proxy. In the app, a `SyncEngine` pushes rows changed since the last push (paths rewritten to `media://<sha256>`, files uploaded), pulls rows since the last server sequence (media downloaded, paths rewritten back), and merges last-write-wins. A first-run role screen decides whether a phone is Dimitris' or a caregiver's.

**Tech Stack:** Node 22 built-ins only (`node:http`, `node:fs`, `node:crypto`, `node:test`); Kotlin `HttpURLConnection` (no new client library) + Gson.

**Spec:** `docs/superpowers/specs/2026-09-05-dimitris-app-design.md` (§7 phase 10, §5 sync contract)

## Global Constraints

- Sync contract: every table row carries `id`, `updatedAt`, `deleted`; `attempts`, `error_logs` and `script_lines` are append-only (union); other tables merge last-write-wins on `updatedAt` (ties keep local). Schedules key on `(itemId, module)` → sync id `"$itemId:$module"`.
- Protocol: `POST /v1/push` `{rows:[{table,row}]}` → `{seq}`; `GET /v1/pull?since=<seq>&limit=500` → `{rows:[{seq,table,row}],seq}`; `HEAD|PUT|GET /v1/media/<sha256>`; `GET /v1/health`. Every request except health carries `Authorization: Bearer <token>`.
- Media: outgoing `imagePath`/`path` values become `media://<sha256>` after upload; incoming `media://` values are downloaded into `photosDir`/`recordingsDir` as `<sha256>.<jpg|m4a>` and rewritten to absolute paths. Missing media never blocks a row.
- Settings: `syncUrl` (DataStore), `syncToken` (SecretStore), `deviceRole` (DIMITRIS default / CAREGIVER), `syncCursor` (server seq), `syncPushedUpTo` (updatedAt). Sync runs on caregiver tap and at app start when configured; Dimitris' phone never shows sync UI.
- Greek-only UI; commits `feat(phase10): ...` with the Co-Authored-By trailer; server code English (developer-facing), README in English with a Greek summary for the father.

### The two-phone story, on one emulator

1. **Phone A** — fresh install, «Φροντιστή», address and token typed in Συγχρονισμός. A new word
   («baklavas» — `adb shell input text` cannot type Greek) with a photo taken on the camera and a
   voice recorded in the editor. Sync: **«Έστειλα 299 γραμμές, πήρα 0 γραμμές. Αρχεία: 182 πάνω,
   0 κάτω.»**
2. **Phone B** — `pm clear`, role, same address and token. Sync: **«Έστειλα 297 γραμμές, πήρα 2
   γραμμές. Αρχεία: 0 πάνω, 2 κάτω.»** Two rows: the word and its recording. Two files: its photo
   and its voice. Its own 297 seeded rows went up and the server ignored every one as a tie —
   *this is the deterministic-seed-id fix working*; before it, this same step pulled 502 rows and
   183 files and left every word on the phone twice.
   * «Λέξεις και εικόνες» holds **one** «Όχι», **one** «Βοήθεια», one of everything else.
   * `files/photos` holds 181 files — the 180 bundled pictograms plus the one photo that arrived.
     (It was 361 before the fix.)
   * The word shows its photo, and «Άκου» plays the recording: `MediaFocusControl` +
     `NuPlayerDriver`, no error, and the file on disk is the content-addressed 77 715 bytes — the
     same size as the take made on phone A.
3. **The edit** — the word is renamed «baklavas-B» on phone B and synced: «Έστειλα 1 γραμμή».
4. **Phone C** — `pm clear`, role, same address and token. Sync: **«Έστειλα 297 γραμμές, πήρα 2
   γραμμές. Αρχεία: 0 πάνω, 2 κάτω.»** The word arrives as **«baklavas-B»**: B's edit won, and
   there is one row for it, not two.
5. **Offline attempts** — with wifi and mobile data switched off (`Active default network: none`),
   two turns of «Λέξεις» were answered on phone C. Back online, one sync: «Έστειλα 4 γραμμές».
   `rows.jsonl` holds **exactly 2 `attempts` rows**, one per turn, and two further syncs added
   none — append-only, on both sides. The second attempt's `itemId` is a version-3 UUID, which is
   a seeded word being practised under the id every phone agrees on.
6. **Settling** — the sync after that: «Έστειλα 0 γραμμές, πήρα 0 γραμμές.»
7. **A wrong token** — «Έστειλα 0 γραμμές, πήρα 0 γραμμές. 1 πρόβλημα.» and
   «Το κλειδί δεν έγινε δεκτό. Έλεγξε το κλειδί στις ρυθμίσεις.» «Σφάλματα» holds **one** row
   (before the dedup fix, one failed sync wrote about two hundred), and
   `grep -a` over `dimitris.db` and its WAL finds the token **0 times**.

The server ended the story with 899 rows and 182 media files, and was stopped afterwards.

### Known limitations, confirmed by the run

* A phone offers rows it has just pulled back to the server once, and the server ignores them as
  ties — that is why phone B's report says it sent 297 rows it had not authored. The push mark is
  one number; making it exact would need a per-row flag and a schema change.
* Nothing prunes the server. Media is never deleted, and 182 files is the whole family's library
  after this run.
* The difficulty levels, the writing hand, the speech rate, the enabled modules and both secrets
  stay on each phone, as ruled.
